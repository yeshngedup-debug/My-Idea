## Method and runtime caveat

- Playwright MCP via Code Mode, desktop viewport, against `localhost:3000`. **No server was listening on port 3000 at the start** (verified with `Invoke-WebRequest`, `Test-NetConnection`, `Get-NetTCPConnection`; no listener on 3000–3002 and no Next.js process). I therefore started a **temporary `npm run dev -- --port 3000`** (the same pattern recorded in `reports/visual-recheck.md`), drove the audit, and stopped it afterwards. This is the one deviation from the spawn instructions, made because the stated premise ("dev server is RUNNING") was false and the task cannot be completed without a server. No production build was run.
- Fresh isolated contexts per role: `audit-admin`, `audit-founder`, `audit-student`, plus `audit-public`. Login used `getByLabel('Email', { exact: true })`, `getByLabel('Password', { exact: true })`, button `Log in`; all three seeded accounts redirected to their role dashboard. Password `LocalTest123!`.
- Per page I captured rendered headings, buttons (text / `aria-pressed` / `disabled`), form fields, `[role=status]`/`[role=alert]`, progressbars, `ol[aria-label]` timelines, `[role=group]`, sticky elements, link counts and horizontal overflow. Interaction probes changed only local UI state (filters, `<details>`, pause toggle, form typing) — **no order, application, verification or shortlist data was mutated**.
- `/founder/shortlists/agreement` is **not a page**: it is `app/founder/shortlists/agreement/route.ts` and streams `shortlist-agreement-template.pdf` as a download (Playwright: "Download is starting"). It is covered as a route with no UI affordance of its own.
- **Concurrent edits landed during the audit** (file mtimes 15:55–15:56 +06:00): `app/student/applications/{page,applications-client}.tsx`, `app/admin/projects/{page,projects-client}.tsx`, and `app/founder/projects/post/post-project-form.tsx`. Every observation below is from the **rendered state after those edits**, so the new status filters and post-form progress bar are recorded as already wired, not as gaps.
- Cross-referenced `reports/visual-recheck.md`, `reports/performance-seo.md`, `reports/orchestrator-audit.md`. Their agreed bar holds: the 320px `/admin` overflow is fixed (`min-w-0` present), stat cards are now `<dl>` ledgers with one leading figure, decorative `Arrow*` links are gone from dashboards, and all seven public routes render 0 horizontal overflow. I found no new violation of the hard rules in current source (no GSAP, no glow/violet/gradient text/marquee/parallax/`scale(0)`/`transition:all`).
- Adjacent, out-of-scope observation for the parent: dashboard `<title>` values still append the brand twice (`Student Dashboard | Bhutan Tech Connect | Bhutan Tech Connect`); the public routes were fixed for this in an earlier pass, the four workspace routes were not.

## How to read the table

- **Real action** = what the user actually came to do, not what the page merely displays.
- **Relevance** = does the mounted component serve that action? "Yes" means keep; "false affordance" means the component promises an action that does not exist.
- **Gap** = a real action with no visible state change / filter / selection / disclosure / progress / keyboard path.
- Recommendations are **reuse of components already in this repo only**. No new widget family, no decorative additions.

## Removals / replacements

1. **`HoverLift` on `/student` "Recent applications" rows** (`app/student/page.tsx:146`). It lifts on hover and shrinks on tap but wraps a non-interactive `<div>`. Either remove the wrapper or make the rows links (top-10 #8). Keep `HoverLift` where it wraps real links (`/founder` recent projects, `/admin` Quick links) — there it is honest.
2. **Two `CaretRight` chevrons on `/contact`** ("Tell us what you need", "Helpful pages"). Small decorative list markers left over from the earlier chevron sweep (`reports/visual-recheck.md` R3). Remove; keep the text links and hover colour change.
3. **Hand-rolled copy button in `/admin/students`** (`admin-students-client.tsx:168-177, 407-413`). Replace with `CopyButton`; no behaviour loss, gains a live region and failure announcement.
4. **Icon family consistency (standards, not interactivity).** The three dashboard overviews import `BriefcaseBusiness`, `UserRound`, `Plus` from `lucide-react` while the rest of the app uses Phosphor. Replace with Phosphor equivalents at 16px / 1.5 stroke / server-side. Sizes are already 16px; only the family is mixed.

## Explicitly NOT recommended (checked and rejected)

- **No `SpotlightCard` removal on `/for-founders`.** Its cursor glow is already deleted; it is a quiet surface around real pricing data. Removing it would lose nothing but adding anything to it would be decoration.
- **No `TextReveal` removal** on `/about` / `/for-founders`: it reveals real headlines, conditioned by reduced motion.
- **No `LocalBridgeDifferences` removal** on `/public` `/about`: duplicated but product-specific content, and the earlier audit already accepted the compact variant. At most vary the `/public` heading (prior L2) — that is a copy change, not a component issue.
- **No `Accordion`/disclosure on the public marketing pages** beyond the existing "Official statistics" `<details>`: there is nothing to disclose that is not already visible.
- **No stat-card, marquee, ticker, glow, blur, gradient text, violet or parallax widget** on any route. Every recommendation above reuses a quiet, keyboard-operable, 24–44px-target component with `focus-visible` and reduced-motion support. No GSAP/anime.js is introduced.
- **No filter on `/privacy`, `/terms`, `/login`, `/signup` or the shortlist agreement route**: there is no real list or selection to filter on those routes.
